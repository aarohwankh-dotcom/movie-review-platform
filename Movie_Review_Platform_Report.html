2. Problem Statement and Project Objectives

2.1 Problem Statement

A digital movie review platform wants users to browse movies and post reviews with a numerical rating. Each movie must display an accurate average rating computed dynamically from all submitted reviews. Furthermore, community integrity requires that a user must be able to edit or delete only the reviews they authored, preventing unauthorized tampering.

The system must ensure that:

  • Movie and Review schemas are designed using Mongoose with normalized document references (ObjectId).
  • Current movie ratings are computed dynamically via MongoDB Aggregation ($match, $group, $avg), eliminating static counter desynchronization.
  • Strict ownership-based authorization middleware prevents non-authors from updating or deleting critiques (returning HTTP 403 Forbidden).
  • Backend validation rigorously enforces rating values between 1 and 5 and rejects empty review commentary.

2.2 Why This Project?

Traditional web platforms that calculate aggregate metrics client-side or maintain static database counters suffer from race conditions, update anomalies, and desynchronization whenever reviews are modified or deleted. Concurrently, insufficient backend authorization often leads to security vulnerabilities where users manipulate foreign resource identifiers. A normalized NoSQL database paired with server-side ownership enforcement guarantees mathematical accuracy and absolute data security.

Proposed Solution

A full-stack RESTful application built with Node.js, Express.js, MongoDB Atlas, and Mongoose ODM. An interactive dark cinematic console communicates via REST with JWT Bearer authentication. Dynamic aggregation pipelines calculate live scores, and custom middleware enforces ownership boundaries as shown in Figure 1.

5.2 Dynamic Average Rating Aggregation Pipeline (Case Study Part 10)

Rather than storing a static counter that risks desynchronization upon edits, CineReview calculates real-time movie ratings directly from the Review collection via a two-stage aggregation pipeline:

const computeMovieAverageRating = async (movieId) => { const objectId = new mongoose.Types.ObjectId(movieId); const stats = await Review.aggregate([ // Stage 1: Match reviews strictly for this specific movie { $match: { movie: objectId } }, // Stage 2: Group reviews and compute arithmetic mean and total tally { $group: { _id: '$movie', averageRating: { $avg: '$rating' }, totalReviews: { $sum: 1 } } } ]); return stats.length > 0 ? { movieId: movieId.toString(), averageRating: Math.round(stats[0].averageRating * 10) / 10, totalReviews: stats[0].totalReviews } : { movieId: movieId.toString(), averageRating: 0, totalReviews: 0 }; };

5.4 Ownership-Based Authorization Middleware (Case Study Part 8)

Ownership authorization is a core academic requirement. When User A creates Review #123, User B must never be permitted to edit or delete it. Custom middleware intercepts mutations and validates identity against the resource author:

const authorizeReviewOwner = async (req, res, next) => { try { const reviewId = req.params.id; const review = await Review.findById(reviewId); if (!review) { return res.status(404).json({ success: false, message: `Review not found with id: ${reviewId}` }); } // Verify author: compare review.user foreign key with decoded req.user._id const isOwner = review.user.toString() === req.user._id.toString(); if (!isOwner) { return res.status(403).json({ success: false, message: 'Forbidden: You are only authorized to edit or delete reviews authored by you', reviewOwnerId: review.user, requesterId: req.user._id }); } req.review = review; next(); } catch (error) { next(error); } };

5.5 JWT Authentication & Password Hashing

Passwords are protected using bcryptjs with 10 salt rounds executed inside a Mongoose pre-save hook. Upon login, the server signs a stateless JWT token containing the user's immutable identifier:

// Pre-save hook hashes password before persisting to database userSchema.pre('save', async function (next) { if (!this.isModified('password')) return next(); const salt = await bcrypt.genSalt(10); this.password = await bcrypt.hash(this.password, salt); next(); }); // Authentication middleware verifying Bearer tokens const protect = async (req, res, next) => { if (req.headers.authorization && req.headers.authorization.startsWith('Bearer')) { const token = req.headers.authorization.split(' ')[1]; const decoded = jwt.verify(token, process.env.JWT_SECRET); req.user = await User.findById(decoded.id).select('-password'); return next(); } return res.status(401).json({ success: false, message: 'Access denied: No token provided' }); };

7.2 Key Findings

  1. Deterministic Precision: Calculating average ratings on-demand through MongoDB pipelines guarantees that modifications immediately reflect in platform scores without desynchronization risks.
  2. Server-Side Security: While hiding edit buttons in the frontend improves user experience, enforcing ownership validation inside Express middleware strictly prevents unauthorized API attacks.
  3. Schema Integrity: Mongoose document references (ObjectId) maintain clean separation between reviews and movies while allowing rapid aggregation across collections.
  4. Payload Resilience: Centralized validation intercepts non-numeric or out-of-range ratings before reaching the database layer, safeguarding data purity.
